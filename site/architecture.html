архитектура

OCaml-сервер, PostgreSQL, границы держит компилятор

Домен не знает про БД и HTTP — это обеспечено раздельными библиотеками dune, а не соглашением. Предупреждения — ошибки. Ошибки — данные, не исключения.

слои

Домен → сервис → интерфейсы

REST, MCP, CLI, веб, чат и Paseo — адаптеры над одним сервисным слоем. Правила и транзакции живут не в HTTP-обработчике.

правила кода

Result вместо исключений

«Переход запрещён» — это Error (Forbidden_by_rules …), не исключение. Домен не бросает. Промиссы в db и api — Lwt_result.t, связка — явный Lwt.bind.

правила кода

Предупреждения — ошибки

В корневом dune включено -warn-error +a: неполный match по статусам не собирается. Добавил статус — обнови все места, где он разбирается, компилятор сам перечислит.

R1 · приёмка

Агент не закрывает свою задачу

Переход in_review → done доступен агенту только при autonomy='auto'. Иначе закрывает заявитель, руководитель или человек с правом приёмки.

R2 · адресный вопрос

needs_input — не «застрял»

Это явное «жду конкретного ответа»: вопрос + asked_to_id. Адресат явный или выведенный (заявитель → руководитель → администратор); выйти может только человек, ответ обязан быть непустым.

R3 · без заявителя

Задачи из чата не висят вечно

Если заявителя нет (бота попросили в чате), приёмку делает руководитель актора-исполнителя, а если и его нет — любой человек-администратор.

интеграции

Каждая функция — там, где ты уже находишься

слой доказательств

mathc: каждое обязательство — с проверяемым доказательством

правило

Claim без control’а — не claim

Control обязан менять предмет и заставлять verifier падать. Падение от синтаксиса или отсутствия базы — не доказательство.

правило

След не редактируется

.math/ — evidence прогонов, не содержимое. Verifier не ослабляется и control не меняется ради зелёного результата.

правило

Человеческое — за человеком

waive, record, authorize — решения владельца. Агент не присваивает себе человеческий review и не создаёт waiver без разрешения.

Сегодня в проекте 98 claim’ов: правило приёмки, идемпотентность миграций, защита применённых файлов, разрешение идентичности и другие обязательства архитектуры.

стек

Почему именно так

язык

OCaml

Сильная статическая типизация ловит неполные match’и по статусам ещё на сборке; Lwt даёт однопоточные промиссы без гонок; результат — один статический бинарь.

хранилище

PostgreSQL

Состояние и правила переходов — в базе. Миграции идемпотентны, применяются целиком в одной транзакции, с контрольной суммой; применённый файл защищён от правки.

сборка

Nix + dune

Флэйк фиксирует тулчейн: OCaml 5.3, dune 3.20, зависимости. dune держит границы библиотек — домен физически не может импортировать db или api.
